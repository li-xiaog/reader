# 架构说明

项目使用 Python 3.12+，提供命令行与 Tkinter 桌面入口。两种入口共用转换和设备备份服务，不启动 Web 服务。

## 分层与依赖

| 模块 | 责任与依赖 |
| --- | --- |
| `models.py` | 定义渠道、格式、请求、章节、书籍、结果，以及适配器和导出器的 `Protocol`。 |
| `cli.py`、`ui/desktop.py` | 收集参数、调用服务、展示真实结果，不实现缓存解码。 |
| `service.py` | 编排输入校验、渠道读取、格式导出、核验报告和最终发布。通过工厂获取具体实现。 |
| `factory.py` | 用枚举到实现类的显式注册表创建渠道适配器和格式策略。 |
| `channels/` | 核对各渠道的书籍身份、章节目录和缓存范围，将读取结果统一为 `BookDocument`。 |
| `codecs/` | 保留各渠道缓存格式的具体解析算法，由对应适配器调用。 |
| `exporters/` | 根据统一书籍模型生成 TXT、Markdown、EPUB 或 XHTML，不访问模拟器。 |
| `infrastructure/backup.py` | 封装 ADB 设备枚举、渠道扫描、数据库副本检查和原始缓存备份，返回后续转换可直接使用的目录。 |
| `infrastructure/database.py` | 将数据库和伴随日志复制至临时目录，比较源与副本哈希，再以只读连接查询；三渠道共同复用。 |

桌面和命令行依赖服务；转换服务通过工厂调用适配器及导出器；领域模型不依赖界面或 ADB。当前设备备份用例和 ADB 操作集中在一个模块中。

## 设计模式的使用范围

- **适配器**：三个渠道各自实现 `ChannelAdapter.load()`，把不同缓存结构转换成相同的章节和资源模型，避免导出器了解渠道细节。
- **策略**：不同格式实现 `Exporter.export()`。同一次转换可以选用多个策略；EPUB 保留微信读书的原生页面、资源及一章多个页面的阅读顺序。模型将原始 `assets` 与可选的 `epub_assets` 分开，番茄适配器提供经过校验的规范化副本及插图，公共导出器不包含渠道解码逻辑。
- **工厂注册表**：入口只传递渠道、格式枚举，由 `create_adapter()` 和 `create_exporter()` 选择实现。当前规模不需要插件发现、依赖注入容器或更复杂的工厂体系。

## 本地转换流程

1. `ConversionService.convert()` 检查源目录、书籍编号、格式和目标目录。目标必须尚不存在，且不能与源目录形成包含关系。
2. 渠道适配器读取实际缓存、核对元数据，返回章节、资源、可靠的总数或未知状态。公共校验拒绝重复章节、乱码和无有效内容等情况；启用 `require_complete` 时，缺章或总数未知都会失败。
3. 在目标父目录下创建独立暂存目录，运行所有所选导出策略，再生成 `index.csv`、章节元数据和 `conversion_report.json`。报告记录实际文件大小、SHA-256、缓存范围和诊断。
4. 所有步骤通过后，将暂存目录重命名为最终目录。任何格式失败都会使整次转换失败，不发布部分格式的成功结果。发生异常时只清理本次暂存目录。

TXT 和 Markdown 不伪造图片正文；仅有原生页面、缺少可导出文本时明确报错。EPUB 校验容器、XML、清单、阅读顺序、导航及页面内部引用；XHTML 输出检查 Windows 文件名及大小写碰撞。

## 模拟器备份流程

1. 使用已有 ADB 列出设备，要求明确选择序列号，并检查在线及授权状态。
2. 扫描所选渠道的真实缓存目录，将数据库主文件和实际存在的日志文件拉取到本地临时目录，再查询真实书籍记录。同书不同账号保留为不同记录，不自动替用户选取。
3. 将选中书籍的缓存及配套数据库、索引等复制到目标同卷暂存目录，检查非空缓存、数据库结构和书籍记录，写入适配器可识别的元数据。
4. 再次确认目标不存在后重命名发布。桌面将成功备份的目录和书籍身份填入本地转换页，转换仍由用户另行执行。

远端 shell 命令仅允许 `find`、`ls`、`stat`，文件复制使用 `adb pull`。实现不调用提权、改权限、应用启停或部署命令。数据库采用逐文件拉取并检查副本，不是冻结模拟器的事务快照；检测到不一致时必须重新扫描或备份。

## 桌面线程与错误边界

`DesktopWindow` 使用单工作线程的 `ThreadPoolExecutor`。工作线程仅调用服务，并将进度、结果或异常写入 `Queue`；Tk 主线程通过 `after()` 定时消费事件，所有控件更新都留在主线程。两页共用任务状态，执行中禁用会改变请求的控件，日志展示实际阶段，不生成模拟百分比。

关闭窗口时取消 Tk 定时器并关闭执行器；已经运行的文件任务继续完成，后台线程不会再操作已销毁的窗口。CLI 将普通失败转换为非零退出码，桌面显示实际异常。缺少元数据、权限不足、目录冲突和解析失败均不会替换成假数据。

发布边界是本地同卷目录重命名：它避免正常异常情况下暴露半成品，但不是跨文件系统事务，也没有实现断电恢复或任务续传。原始备份、导出物、账号信息和临时验证文件不应进入版本管理。

## 扩展步骤

- 新增渠道：增加 `Channel` 枚举，实现适配器及必要 codec，在工厂注册；需要设备备份时增加对应扫描、复制及副本验证逻辑，并补充桌面渠道名称。
- 新增格式：增加 `ExportFormat` 枚举，实现导出策略并注册工厂。策略只写入传入的暂存目录，返回实际生成的文件；无法表达的内容应明确报错。
- 修改公共模型或完整性规则：同步检查所有适配器、导出器及两种入口，使用已有真实缓存验证章节顺序、缺失报告和输出边界。验证文件与结果保留在 Git 管理范围之外。
